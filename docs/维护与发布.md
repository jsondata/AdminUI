# AdminUI 维护与发布

AdminUI 的运行入口是浏览器脚本与样式，不要求用户安装 Node、Python 或构建工具。Vue、Element Plus 和 Tabler 是运行时依赖；图表示例与富文本分别按需加载 ECharts 和 UEditor Plus。`examples/mock_server.py` 只用于可选的本地接口演示。

## 修改与验证

1. 修改核心行为时保持 `src/admin-ui.js` 的浏览器全局入口和已有 API；不把演示页逻辑放入核心。
2. 运行 `node --test tests/workspace.test.cjs`，以及涉及的 `node --check`。Node 仅用于开发验收。
3. 通过静态服务器打开完整演示、`examples/starter.html`、`examples/components.html` 和 `examples/integration.html`；检查主要修改的交互、桌面与手机布局、浅色与深色主题。
4. 涉及接口适配时可运行 `python3 examples/mock_server.py`，通过 `examples/integration.html?api=1` 和 `examples/backend.html` 测试；服务仅限本机演示，不可部署为生产接口。
5. 更新 `README.md`、组件指南及 `VALIDATION.md`；只记录实际验证过的内容，保留尚未验证的浏览器和后端边界。

## 依赖与发布

- 更新上游浏览器发行文件时，记录来源、版本和许可证，保留许可证和上游要求的 NOTICE；核对 `THIRD_PARTY_NOTICES.md` 和 `adminui.json`。
- 保持运行时无需构建，避免让示例专属依赖成为所有页面的必需资源。富文本和图表按需加载。
- 更改公开 API 或行为时同步更新组件指南和示例，明确兼容性变化；测试保存的标签、主题和原有使用方式。
- 发布前检查静态路径、资源缓存版本、空状态和错误状态；在实际支持的浏览器环境中验收。没有验收过的浏览器不得标注为已支持。
- 生产项目必须自行接入服务端认证、授权、CSRF 防护、真实上传和数据校验。本地模拟令牌及固定账号不可用于生产。

当前核心代码集中于单一浏览器入口，便于无构建接入；演示和业务代码与核心分离。若未来需要拆分，需保持现有单文件入口或提供兼容发行包，不能把构建步骤强加给使用者。
